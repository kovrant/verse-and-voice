# Student Management, Fees, and Activity Auditing

Quran Academy manages the entire administrative lifecycle of enrolled students, including credentials, tuition fee accounting, device detection, and real-time interaction logs.

---

## 👥 Student Lifecycle & Profiles

Students are stored in the `students` table:
* `status`: `"Reading"` (actively enrolled), `"Completed"` (graduated), `"Left Uncompleted"` (withdrawn).
* `started_at` & `ended_at`: Date-only `YYYY-MM-DD` strings.
* `qaida_media_id`: Nullable foreign key to assigned starter Qaida.
* `class_time`: Stored as `"h:mm AM/PM PKT"`.
* `class_days`: Array of integer days `0..6` (0 = Sunday ... 6 = Saturday).

---

## 💳 Tuition Fees & Currencies

* **Currencies Supported:** `PKR` (Rs), `USD` ($), `GBP` (£), `SAR` (﷼), `BHD` (BD).
* **Ledger Table (`fee_payments`):**
  * Tracks payments on a monthly cadence: `student_id`, `month`, `year`, `is_paid`, `paid_at`.
  * Allows backfills and historic audit tracking.

---

## 📊 Activity Auditing (`/api/activity`)

Student activity inside the learning portal is tracked for parental insight and teacher supervision:
* **Events Captured:** `page_view`, `link_click`, `click`, `para_open`, `pdf_page`.
* **Batching Strategy (`src/lib/activity-log.ts`):**
  * Buffers client clicks and flushes when buffer reaches `MAX_BUFFER = 20` or every `FLUSH_INTERVAL_MS = 4000`.
  * **Page Hide / Tab Close:** Flushed via `navigator.sendBeacon("/api/activity")` so navigation does not drop trailing events.
  * **Identity Derivation:** The `/api/activity` endpoint securely extracts the `student_id` from the HTTP session cookie; the client never provides its own identity.

---

## 🔔 Notification Deduplication (`src/lib/notify.ts`)

System notifications are generated by the server using the service-role client:
* **The Deduplication Window:** Multiple actions (e.g. React StrictMode double mounts, rapid tab switches, or retries) can trigger notification events.
* **Server Guard:** `notify()` suppresses duplicate notification inserts for the same student, type, and target if one already exists within the configured deduplication window.
